## 1. 目的と範囲

家庭内LANのPC・スマートフォン・タブレットから、専用アプリを導入せずに原稿台のスキャナーを使用する。書類、写真、図版、小物、実験対象などを同じ操作で取り込めるようにする。原稿のプレビュー、任意の矩形指定、解像度・色・形式の選択、取得、閲覧、保存を中核とする。

ECHOの補正実験は終了扱いとし、通常画面からECHO・MINUS ONE固有の補正、極座標解析、境界フィッティング、DVD中心検出、補正CSV・ISO関連機能を分離する。汎用的な矩形範囲指定、物理座標、画像ビューア、履歴、計測用原本保存は継承する。過去の研究コード・データは履歴または別アプリに保全し、削除や上書きを行わない。DVDライター制御は本アプリの対象外。

優先度：P0＝初版必須、P1＝実用拡張、P2＝後続検討。

## 3. 画面と利用フロー（P0）

### 3.1 メイン画面

PCでは左側に設定パネル、右側に原稿台プレビュー／取得画像。スマートフォンでは設定と画像を縦に配置し、タッチで矩形選択できる。画面上部に機器名、接続状態、実行中ジョブ、空き容量警告を表示する。

設定パネル：原稿サイズ（全面/A4安全範囲/A5/B5/はがき/任意）、解像度、色、保存形式、ファイル名、取得範囲のmm入力、矩形指定モード、取得可否・推定画素数のリアルタイム表示、取得方式（自動/一括/分割）、プレビュー・スキャン開始・停止。用紙サイズが原稿台を超える場合はエラーを表示し、黙って縮めない。

操作順：原稿をセット → 200dpiプレビュー（全面） → 画像上で矩形選択またはmm入力 → 条件設定 → スキャン開始 → 取得画像確認 → ダウンロード。プレビューなしで全面または既知範囲を指定することも可能。

プレビューは任意。表示中画像のIDを保持し、他端末の取得やポーリングで画像や範囲を勝手に変更しない。原稿が動いた場合は再プレビューを促す。

### 3.2 画像ビューア

P0：画面に合わせる、100%（画像1px＝CSS 1px）、拡大縮小、パン、90°回転、矩形選択、座標表示、画像寸法・dpi・色・容量の確認。拡大は表示のみ。元画像は不変。

P1：明るさ・コントラスト・ガンマの表示調整、グリッド、距離計測、全解像度部分表示、トリミング・回転を別ファイルに書き出す。計測値には未校正の公称座標である旨を表示する。任意回転時も選択座標を原稿台へ正しく逆変換する。

### 3.3 履歴

P0：新しい順、サムネイル、日時、原稿名、解像度、形式、範囲、成功/失敗/部分成功、ダウンロード。既存PNG+JSONの読み取り互換を維持し、古いメタデータに無い項目は不明と表示する。履歴選択を保持し、自分が開始したスキャンの完了時のみ、途中で別画像を選んでいなければ自動表示する。

P1：検索、複数選択、ZIPダウンロード、名前・タグ編集、明示的なゴミ箱移動・復元。原本の上書きは禁止。

## 4. スキャン設定

| 設定 | 初版仕様 |
|---|---|
| プレビュー | 200dpi、カラー、全面。表示用縮小版生成可 |
| 既定本スキャン | 300dpi、カラー、PNG、原稿台内の選択矩形または全面 |
| 解像度 | 実機の許可値10段階。4800/9600は補間ラベルを表示 |
| 色 | カラー、グレー、白黒。高速カラー・誤差拡散は詳細設定 |
| 取得時の保存 | PNG（既定・可逆）、JPEG（容量優先）。ダウンロード形式とは独立 |
| ダウンロード | PNG、JPEG（品質・色差サブサンプリング指定）、単ページPDF（P0）、TIFF（P1） |
| 原稿範囲 | 左、上、幅、高さ（mm、0.1mm単位）。画像上の矩形と双方向同期。右/下の境界チェック必須 |
| 取得方式 | 自動（既定）、一括（安全上限内のみ）、分割 |
| 追加情報 | 推定画素数、非圧縮容量、分割数、光学/補間区別。時間は実績がある場合のみ目安表示 |

PNG/JPEG/PDF等の出力は機器の転送形式と区別する。PDFはスキャン結果から生成し、原本画像を保持する。JPEG保存が機器側メモリ負荷を軽減するとは仮定しない。True Gray/白黒などは実機で使用可能だが、対象によって階調喪失がある。

### 4.1 位置指定スキャン：矩形編集（P0）

取得したい範囲（要求ROI）と、1回で取得可能な範囲（実行タイル）を別々に扱う。35MPを超える要求ROIも選択でき、自動分割計画を提示する。解像度変更で要求ROIを無断縮小しない。

| 指定モード | 動作 | 優先度 |
|---|---|---|
| 自由矩形 | 任意の2点をドラッグして範囲を作成 | P0 |
| 固定サイズ | 幅・高さを数値指定し、位置だけ移動 | P0 |
| 最大面積 | 指定dpi・機器プロファイルの一括上限を超えない範囲で縦横比を調整。原稿台境界等で必要なら縮小 | P0 |
| 縦横比固定 | 1:1、4:3、3:2、A4比率、任意比率 | P0 |

- 選択済み矩形は内部ドラッグで移動、四隅と四辺のハンドルでサイズ変更。固定サイズではハンドルを無効化。タッチでは明示的な編集/パンモードを提供し、ピンチ操作との衝突を避ける。
- 左X、上Y、幅W、高さHを0.1mm単位で入力でき、右X、下Y、中心座標も表示。画像上の編集と数値欄は即時同期。中心位置の指定にも対応。
- 方向キーで0.1mm、Shift+方向キーで1mm移動（入力欄操作時を除く）。矩形作成・移動・リサイズ・数値変更は取り消し可能。
- 原稿台全体を薄い背景、取得済み画像範囲を別色で表示。定規・mmグリッドを切替可能。原稿台外は明示的に拒否し、数値入力を無断補正しない。ドラッグ操作では境界で停止させる。
- プレビューや過去の部分スキャンから追加の高dpi範囲を選択できる。座標は常に原稿台左上を原点とした絶対mm。画像の拡大、パン、回転、CSS表示調整後も逆変換を行う。画像の実画素寸法と取得時のROIメタデータを用い、名目dpiだけで画像座標を求めない。
- 現行APIの最小幅・高さ3mm、0.1mm丸めを初期プロファイルとして継承。丸め後の条件で最終検証する。公称原稿台210×291mmと現行APIの211×355mmは区別し、安全側の原稿台プロファイルを適用する。未校正の物理座標であることを明示。

### 4.2 矩形条件のリアルタイム可視化（P0）

設定変更のたびに要求ROIの幅・高さ・面積、推定画像寸法、画素数、非圧縮データ量、1回の上限に対する比率、分割数を更新する。判定は「一括条件内（計算上）」「分割が必要」「原稿台外/無効」「実測上の制約あり」を文字と色で区別する。緑色でも実機成功の保証を意味しない。

35MPのみを仮定した名目面積上限は `A = 35,000,000 × (25.4 / dpi)^2` mm²。現在の幅Wに対する最大高さは `min(291−Y, A/W)`、現在の高さHに対する最大幅は `min(210−X, A/H)`。実装時は機器プロファイル、安全余裕、画素切り上げ、0.1mm丸め、個別幅・高さ制約を適用してサーバー側で再計算する。

| dpi | 名目最大面積 (mm²、概算) | 名目最大正方形の辺 (mm、概算) |
|---:|---:|---:|
| 300 | 250,896 | 500.9 |
| 600 | 62,724 | 250.4 |
| 1200 | 15,681 | 125.2 |
| 2400 | 3,920 | 62.6 |
| 4800 | 980 | 31.3 |
| 9600 | 245 | 15.7 |

この表は原稿台寸法や安全余裕を適用する前の概算であり、実際に指定できる最大寸法ではない。例えば2400dpi・幅80mmの場合、35MPだけなら高さ約49mmが上限となる。正方形の最大辺を個別の幅・高さ上限として扱ってはならない。

- 選択矩形上に寸法ラベル、現在の幅での最大高さ（破線）、現在の高さでの最大幅を表示。画素数ゲージと数値を併記。
- 幅×高さの許容領域グラフ（双曲線 `H=A/W` と現在の点）を詳細表示に用意する。実測成功・失敗点を重ねられる設計にする。
- 上限を超えた場合の選択肢：自動分割、幅を維持して高さを縮小、高さを維持して幅を縮小、縦横比を維持して縮小、dpiを下げる。縮小・dpi変更は利用者が明示選択した時だけ適用する。
- 分割計画は要求ROI上にタイル番号、境界、重複域を描画する。プレビューと最終実行は同じサーバー計画を使用し、条件変更時は再計画する。
- 取得実績は機器・dpi・色モード・物理ROI・実画素数・経過時間・成否・エラー種別とともに蓄積する。35MP以下でも失敗した条件を区別し、少数の成功例のみで安全領域を自動拡大しない。幅・高さ・走査位置などによる機器依存性を検証できるようにする。

### 4.3 複数矩形・プリセット（P1）

- 画像上に複数の独立したROIを登録し、番号・名前・幅高さ・位置・dpi・色モード・保存形式・分割方式を個別に設定。選択、複製、移動、削除、並べ替えが可能。
- 同一サイズのROIを複製して位置だけを変える比較測定を支援する。固定サイズプリセットや複数ROI一式を保存・再利用できる。
- 原稿を動かさず、登録順に逐次スキャンする。複数ROIを1つの親ジョブとして扱い、各ROIを子ジョブ、各分割画像をタイルとして記録。外部からの同時スキャンは拒否し、I/O障害時には後続ROIも停止。正常取得済み原本は残す。
- 保存したプリセットは原稿台絶対座標と機器プロファイルを保持する。再セット時は位置ずれに注意を促し、実行前にプレビューと計画を確認できるようにする。ROI個別または全体をZIPで出力可能。

## 5. 高解像度分割スキャン（P0）

### 5.1 計画

理論画素数は `ceil(width_mm*dpi/25.4) × ceil(height_mm*dpi/25.4)`。実機では丸めがあるため、機器プロファイルの余裕係数と安全寸法を追加する。35MPはソフトウェア上限であり、それ以下の実機成功を保証しない。

自動方式は安全な一括取得が可能なら一括、超過時は矩形をX/Y方向に分割する。重複幅は既定2mm（設定可能、狭いROIでは縮小）。各タイルの重複を含めた取得範囲が安全上限内であることを確認する。分割計画を実行前にプレビュー上へ表示する。分割ジョブは逐次実行し、並列スキャン禁止。実測で安全性が確認された機器プロファイルを用いる。

| 210×291mm 全面 | 名目画素数 | RGB非圧縮量（概算） |
|---|---:|---:|
| 200dpi | 3.8 MP | 11.4 MB |
| 300dpi | 8.5 MP | 25.6 MB |
| 600dpi | 34.1 MP | 102 MB |
| 1200dpi | 136 MP | 409 MB |
| 2400dpi | 546 MP | 1.64 GB |

600dpi全面は35MPに近く、余裕係数や機器実測次第で分割する。2400dpi全面は35MP基準だけでも最低16タイル相当（重複・端数・安全寸法により増加）。4800/9600dpi全面は初版では不可とし、小領域のみ許可する。全タイルを一括でメモリに読み込まない。

### 5.2 保存と合成

- 各タイルの原本、座標、実画素数、取得時間、成功状態、SHA-256を保存する。分割境界、重複、取得順を事前表示し、手動の行列数・重複幅指定も同じ安全検証を通す。
- P0：原本タイル一式とmanifestのZIP（サーバー側ストリーミング）、全体の低解像度モザイクを提供する。モザイクには未取得領域を表示する。
- P1：重複領域で画像位置合わせを行い、高解像度合成画像を生成する。大容量画像はストリップ処理またはタイルTIFF等を用いる。元タイルは変更しない。位置合わせの確度が低い場合は未検証の合成として表示し、無断で非線形変形を行わない。
- P1：失敗タイルのみ再取得する機能。原稿位置・機器設定の一致を利用者が確認してから再開する。

### 5.3 障害時

I/Oエラー時は直ちに次タイルを開始しない。スキャンプロセス終了と排他解除を確認し、機器復旧を案内する。自動再試行は既定なし。部分成功したタイルは保存し、完全成功と区別する。停止時も取得済み原本を残す。

## 6. 保存・出力

サーバー内はジョブID単位のディレクトリ。例：`scans/20261124T060700Z-<id>/`。

- `manifest.json`：schema_version、job_id、created_at、finished_at、device/model、source、requested_roi_mm、requested_dpi、mode、format、strategy、status、error、tile一覧、派生ファイル一覧。
- `original.png` / `original.jpg` または `tiles/tile-0001.png` 等：取得時の保存形式に応じた原本。JPEG原本は非可逆である旨を記録する。
- `preview.jpg`、`thumbnail.jpg`：表示用派生物。原本とは明確に区別。
- `exports/`：JPEG、PDF、TIFF、ZIP等。

P0：一括成功はPNG/JPEG原本または選択した形式、PDF、分割成功はタイルZIPと概要プレビューを取得できる。ファイル名は利用者指定名を正規化し、内部IDとは分離する。保存は一時ファイルから検証後にatomic rename。失敗した不完全ファイルを正常原本として公開しない。既存履歴は読み取り専用アダプターで統合し、移行を繰り返しても重複・消失しない。

P1：複数ページPDF（ページ追加、並べ替え、削除、回転、最後に一括PDF化）、原本一括エクスポート、複数ROI一括出力。P2：OCR（日本語/英語、ローカル実行）、検索可能PDF、任意のLAN共有先への明示保存。

### 6.1 JPEGダウンロード・形式変換（P0）

取得時の保存形式とダウンロード形式を独立させる。PNGで取得した履歴画像も、再スキャンせずJPEGとしてダウンロード可能とする。原本取得・原本ダウンロードは従来通り維持し、JPEG出力がPNG原本を上書きしない。

| 設定 | 仕様 |
|---|---|
| 出力形式 | PNG / JPEG / PDF（P0）、TIFF（P1） |
| JPEG品質 | 1〜100、既定95。書類・写真向けに85等のプリセット |
| クロマサブサンプリング | 4:4:4（既定）、4:2:2、4:2:0。グレーでは非適用 |
| 出力解像度 | 原寸既定。任意の縮小指定可。拡大で光学情報を増やさない |
| DPI情報 | 原寸時は取得設定dpiをメタデータに保持。縮小時は物理範囲に対応する値に更新。実画素寸法・公称dpi・変換条件は別途記録 |
| 出力対象 | 原本全体、選択矩形のみ、表示調整反映画像（調整機能と同時にP1） |
| ファイル名 | 任意指定、拡張子 `.jpg` / `.jpeg`。内部保存IDと分離 |
| 分割・複数ROI | 各原本タイル/ROIのJPEG、JPEG一式のZIP（複数ROIはP1）。原寸合成JPEGは合成機能が利用可能になった段階で提供 |
| 設定記憶 | ブラウザ単位で前回の出力設定を記憶 |

- 取得時からJPEGで保存する容量優先モードも提供する。SANE側のJPEG品質指定・サブサンプリング制御が保証できない場合は、対応可能なサーバー側エンコード経路を使用し、実際に適用した設定を記録する。制御不能な設定を適用済みと表示しない。ホスト側JPEG変換はスキャナー内部転送量の削減を保証しない。
- 原本がJPEGで、原寸・未編集の原本ダウンロードを選択した場合は再圧縮せず元ファイルを返す。変換・トリミング時は非可逆再圧縮であることを明示する。JPEGからPNGへの変換で失われた情報は復元されない。
- 出力画面には形式、品質、色差、対象、画像寸法、原寸/縮小、ファイル名を表示し、JPEGと原本ダウンロードを履歴から直接選べるようにする。
- 変換はbr00サーバー側で実行。元画像、変換条件、生成物を紐付け、ブラウザ側で巨大画像をCanvas展開しない。空き容量・メモリ・最大画像寸法を確認し、巨大合成画像のJPEGエンコーダー制限を超える場合はタイルJPEG/ZIPまたは対応形式を提案する。非対応のサイズを黙って縮小しない。
- JPEGの出力は元画像の画素数・座標の情報を保持しても、画素値の完全一致を保証しない。定量解析の取得原本にはPNGを既定とする。

## 7. サーバー／API

ブラウザは操作・表示を担当し、スキャン・ファイル保存・形式変換はbr00で行う。Python標準ライブラリを基礎とし、画像変換・PDF生成・巨大画像処理に必要な依存だけ明示導入する。WebGPUは必須にしない。

| HTTP | API（再設計案） | 機能 |
|---|---|---|
| GET | `/api/health` | サービス生存確認（実機操作なし） |
| GET | `/api/devices` | 利用可能機器・安全プロファイル・能力 |
| GET | `/api/status` | 機器/実行中ジョブ状態 |
| POST | `/api/jobs/plan` | ROI検証、画素数・分割計画 |
| POST | `/api/jobs` | プレビューまたは本スキャン開始、202とジョブID |
| GET | `/api/jobs/{id}` | 状態・経過・タイル数・エラー |
| POST | `/api/jobs/{id}/cancel` | 中断要求 |
| GET | `/api/history` | 履歴（ページング） |
| GET | `/api/jobs/{id}/files/{fileId}` | 原本・派生ファイルの取得 |
| POST | `/api/jobs/{id}/exports` | JPEG/PDF/PNG等の派生物生成。形式・品質・色差・対象ROI・縮小条件を指定 |
| GET | `/api/jobs/{id}/exports/{exportId}` | 変換ジョブ状態と出力fileIdの確認 |

計画APIは要求ROI、正規化済みROI、実行タイル、各推定画素数、上限、判定理由、警告、機器プロファイル版を返す。複数ROI対応時はROI別計画も返す。サーバーは実行直前に同じ制約で再検証し、古い計画や不整合な要求を拒否する。JPEG出力APIでは品質1〜100、色差方式、対象、寸法などを許可値検証し、変換はスキャン処理とは別の制限付き処理として管理する。

現行 `/api/scan`、`/api/cancel` は旧クライアントに必要なら互換アダプターを用意する。ECHO/MINUS ONE専用APIは研究アプリ側へ分離し、通常サービスから依存を外す。

ジョブ状態：`queued → scanning → processing → completed`。異常時 `failed` / `partial`、停止時 `cancelling → cancelled`。スキャン進捗はタイル完了数、経過時間、SANEが信頼できる場合のみ走査率。取得不能な進捗は不定表示とし、架空の%を出さない。

同時操作は1機器1ジョブとし、実行中の新規要求は初版ではHTTP 409。スキャンプロセスだけでなく、既存Actions・CLIの取得処理と共通のOSレベル排他（flock等、ロックパスを全取得経路で統一）を導入する。プロセス内RLockだけでは不足。機器列挙も実行中に不要なアクセスを行わない。

タイムアウトは現行600秒を初期値として1タイル単位で管理し、機器プロファイルで調整可能。キャンセル時は子プロセスグループ停止、必要なら段階的強制終了、後片付け完了まで排他維持。Webブラウザが閉じてもジョブは継続し、再接続時に状態を復元する。サービス再起動で未完了ジョブは中断として記録し、無断再走査しない。

## 8. 非機能・セキュリティ

- LAN専用。現行は認証なしのため、信頼済みLANにファイアウォールで制限し、WAN公開しない。共有利用・外部アクセス時は認証付きHTTPSを必須とする。
- 状態変更APIはOrigin/Host検証、CSRF対策、JSON限定。任意のコマンド、パス、デバイス引数を受理しない。固定引数列で `scanimage` を実行する。
- 出力ファイルはジョブIDと許可済みfileIdで参照し、パストラバーサル・シンボリックリンク逸脱を防止する。
- 容量は実行前とタイル間に確認し、原本・派生物・一時ファイルの余裕を確保する。不足時は新規取得を拒否する。自動削除は既定無効。
- 巨大PNGをブラウザのCanvasやサーバーRAMに一括展開しない。通常は縮小画像を表示し、詳細はROIまたはタイル表示とする。ダウンロードはストリーミング。
- 原稿データをGitHub・クラウドへ自動転送しない。ログに原稿画像や文書内容を出力しない。
- 日本語UI、キーボード操作、タッチ対応。外部CDNに依存せずLAN内だけで動作する。

## 9. デプロイ・移行

現行 `apps/scanner-web/` を汎用アプリに再構築する。研究専用コードは既存 `apps/disc-inspector/` または別研究ディレクトリへ分離（研究アプリとの統合は別判断）。ECHO専用参照artifactのダウンロードを汎用デプロイの必須条件から除外する。

現行 `.github/workflows/br00-scanner-web-deploy.yml` を更新する。テスト成功後、コードのみステージングして切り替える。実行中のスキャンがあればデプロイを中止または延期し、強制終了しない。`/home/runner/scanner-web/scans/`、旧履歴、研究用原本を保護する。デプロイ後は `/api/health` と静的資産、再起動後の履歴を確認する。失敗時は旧版へロールバックできる構成とする。

URL・ポート・runner権限・cron @rebootは初版で維持する。将来systemd化する場合は別作業として扱う。

## 10. 受け入れ試験

| ID | 合格条件 |
|---|---|
| T01 | 200dpi全面プレビューが取得でき、矩形とmm入力が相互反映する |
| T02 | 300dpi A4安全範囲カラー取得、PNG原本・JPEG・単ページPDFを確認できる |
| T03 | 600dpi、2400dpi小領域、4800/9600dpi小領域の設定検証と原本寸法記録ができる |
| T04 | 2400dpi全面計画が35MP等の安全上限を超えないタイルへ自動分割され、全範囲を覆う（実機は安全な小領域の複数タイルから段階検証） |
| T05 | 分割タイルの原本・manifest・ZIP・概要が取得でき、部分失敗を成功と誤表示しない |

| T07 | キャンセル・タイムアウト・USB切断・ディスク不足で安全停止し、成功済み原本を保全する |

| T09 | 画面拡大・回転・スクロール・タッチ操作後も物理座標変換が正しい |
| T10 | 無効な範囲・dpi・パス・不正Originを拒否する |
| T11 | 再配備・再起動で旧履歴・原本・cron設定が維持される |
| T12 | 通常画面にECHO/MINUS ONE専用UIが存在せず、研究artifactなしで起動する |
| T13 | 自由矩形・固定サイズ・最大面積・縦横比固定が機能し、移動・8ハンドル・数値入力・キー操作でROIを編集できる |
| T14 | dpi・幅・高さ変更時に上限、推定画素数、最大幅高さ、分割図が更新され、要求ROIが無断変更されない |
| T15 | 35MP境界、端数丸め、3mm最小、原稿台端、細長い矩形、実測安全条件をサーバーとUIで同じ判定にできる |
| T16 | 過去の部分画像を拡大・回転後に指定したROIが原稿台絶対mmと一致する |
| T17 | 複数ROIの複製・保存・再読込、個別dpi、逐次実行、障害停止が正しい（P1） |
| T18 | PNG原本と旧履歴から再走査なしでJPEG生成でき、原本SHA-256が変わらず原寸寸法が一致する |

| T20 | JPEG原本の無変換ダウンロードはバイト一致し、変換した出力は原本と分離する |
| T21 | 分割原本のJPEG一括ZIPが正しく、巨大画像の制限・空き容量不足でも原本が保持される |

CIは模擬scanimageを使う単体・API・UI・回帰試験を主体とし、実機試験は原稿セットと利用者の許可がある場合に別実行する。実機エラーのないことを確認できるまでは高dpi全面を成功済みとは扱わない。

## 11. 実装順序

1. P0基盤：ECHO依存分離、既存履歴保全、汎用UI、能力・安全プロファイル、排他・状態管理。
2. P0取得：プレビュー、矩形4モード・座標同期・取得可否表示、各色モード、PNG/JPEG取得、JPEG出力設定、単ページPDF、履歴・原本ダウンロード。
3. P0分割：分割計画、逐次実行、原本タイル保存、manifest、ZIP、縮小概要、障害対応。
4. P0運用：回帰テスト、実機小領域試験、デプロイ・ロールバック・再起動試験。
5. P1：複数ROI・プリセット、高解像度合成、複数ページPDF、編集・検索、失敗タイル再取得。
6. P2：OCR、LAN共有出力、複数機種・eSCL等の互換インターフェース検討。
