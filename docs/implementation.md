# 実装・移行方針

## 安全境界
- 開発・CIは GitHub hosted ubuntu-24.04、モックのみ。br00や既存8765番、研究データには触れない。
- 実機は明示的な --device 指定と --allow-hardware の両方を要求。旧サービスが同じ排他ロックを使わない限り並行運用不可。
- 既定は localhost:8766、専用データディレクトリ。公開インターネットに出さない。LAN公開にはアクセス制御が必要。
- 35MPの上限に対し余裕を持たせる。210×291mmは公称原稿台の安全側設定。実画像サイズを保存し、真の光学解像度とは区別する。

## 初期スコープ
矩形選択・数値編集・モード・解像度連動・分割計画・逐次取得・履歴・PNG/JPEG出力を優先する。合成画像の精密位置合わせ、複数ROI、PDF、旧履歴移行、実機試験、実測安全領域の確定は後続。未実装を完了扱いしない。

## 切り替え（未実行）
1. 別会話の実機スキャンが全て完了したことを確認。
2. 旧サービス・Actionsのスキャン利用を停止し、共有OS排他を統一。
3. 別ポートで小ROIの実機スキャンを行い、寸法・形式・キャンセル・再接続を確認。
4. 旧原本を読み取り専用で保全、移行を検証。
5. 利用者承認後に8765番を切り替え。失敗時は旧サービスを復旧。

## 検証
- Python HTTP統合試験：分割、原本の不変性、JPEG/PDF出力、ZIP、エラー応答。
- Chromium実ブラウザ試験：DPI変更で矩形保持、分割境界、一括サイズ調整、数値・キー・固定矩形操作、スキャン結果表示、JPEGダウンロード。
- ZIPは完了済み原本とmanifestを保存し、部分成功も明示する。高解像度合成は未実装。

## 複数ROI・プリセット
- 予約は最大32領域、合計256タイル・10億取得画素以内。全条件を事前検証し単一の排他ジョブとして順次取得する。各原本のROI番号、DPI、モードをmanifestに記録。失敗時は停止し完了済み原本を保持。
- プリセットはブラウザのlocalStorageに最大50件。サーバー間・端末間共有は未実装。予約キューはページを閉じると消える。
- API: POST /api/batch-plan と POST /api/scan の regions 配列。従来単一ROIのAPIと互換。

## 中断復旧（未取得タイルのみ）
- 同一ジョブID・同一計画で再開。対象物が動いていないことを明示確認する。自動再開はしない。
- 完了原本の取得時SHA-256・サイズ・画像検証を照合。旧チェックサムなしの部分ジョブ、原本改変・消失、未登録の原本ファイルがある場合は再開拒否。原本を上書きしない。
- 失敗タイル番号・取得試行回数・直前エラーをmanifestへ記録。失敗で中断し未取得分を明示再開。プロセス中断で running が残った場合もOSロックとアクティブ状態を確認してから再開可能。ただし原本公開直後でmanifest未更新の場合は安全側に拒否。
- POST /api/resume {id, confirmedUnmoved:true}。実機とモックの混在は禁止。実機の再開は同一device指定のみ。
- CIでは第2タイルのI/Oエラーを模擬し、再開時の原本ハッシュ・更新時刻不変性、再取得対象、UI確認ダイアログ、結果表示を検証する。実機回復は未検証。

## 公称座標の分割合成
- 完了済みジョブのみ、ROI単位に合成。異なる解像度のROIを混ぜない。絶対mm座標から公称DPIの画素格子へ変換し、実画像寸法が異なるタイルはLanczosでリサンプルする。重複部は後のタイルを優先し、全画素の被覆を検証する。
- プレビューは長辺1600px以下、原寸PNGは10億画素以内。ディスク上RGBラスタへ16行単位で書き、PNGを行単位に圧縮。全画像をRAM展開しない。ただし入力タイル1枚分と変換時の一時画像はRAMに必要。空きディスクは出力画素×7+50MBを要求。派生出力は同時1件、リクエスト完了時に一時ファイルを削除。
- 元画像の変更なし。API /api/mosaic-plan, /api/mosaic。合成は未校正で、精密な位置合わせ・重複領域の評価・色合わせは今後。原寸JPEG合成は未実装。大容量の実機性能は未検証。
