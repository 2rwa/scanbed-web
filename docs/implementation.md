# 実装・移行方針

## 安全境界
- 開発・CIは GitHub hosted ubuntu-24.04、モックのみ。br00や既存8765番、研究データには触れない。
- 実機は明示的な --device 指定と --allow-hardware の両方を要求。旧サービスが同じ排他ロックを使わない限り並行運用不可。
- 既定は localhost:8766、専用データディレクトリ。公開インターネットに出さない。LAN公開にはアクセス制御が必要。
- 35MPの上限に対し余裕を持たせる。210×291mmは公称原稿台の安全側設定。実画像サイズを保存し、真の光学解像度とは区別する。

## 初期スコープ
矩形選択・数値編集・モード・解像度連動・分割計画・逐次取得・履歴・PNG/JPEG出力を優先する。合成画像の精密位置合わせ、複数ROI、PDF、旧履歴移行、実機試験、実測安全領域の確定は後続。未実装を完了扱いしない。

## 切り替え（未実行）
1. 別会話の実機スキャンが全て完了したことを確認。
2. 旧サービス・Actionsのスキャン利用を停止し、共有OS排他を統一。
3. 別ポートで小ROIの実機スキャンを行い、寸法・形式・キャンセル・再接続を確認。
4. 旧原本を読み取り専用で保全、移行を検証。
5. 利用者承認後に8765番を切り替え。失敗時は旧サービスを復旧。

## 検証
- Python HTTP統合試験：分割、原本の不変性、JPEG/PDF出力、ZIP、エラー応答。
- Chromium実ブラウザ試験：DPI変更で矩形保持、分割境界、一括サイズ調整、数値・キー・固定矩形操作、スキャン結果表示、JPEGダウンロード。
- ZIPは完了済み原本とmanifestを保存し、部分成功も明示する。高解像度合成は未実装。
